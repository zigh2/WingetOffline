# قرارات التصميم الأساسية

سجلّ قصير لأسئلة تتكرر، مع سبب كل قرار، كي لا نعيد النقاش نفسه.

## هل يبقى المشروع بالكامل C# أم تُبنى نسخة ثانية بلغة أخرى (Python وغيرها)؟

**القرار: يبقى C# (.NET 8) لكل شيء، ولا تُبنى نسخة ثانية.**

| المعيار | C# / .NET | Python | Rust / Go |
|---|---|---|---|
| واجهة Windows أصلية وتجربة ثابتة | **WPF جاهزة ومجرَّبة** | Tk/Qt: أثقل وأقل أصالة | غير ناضجة (egui/Slint) أو WebView |
| ملف تنفيذي واحد | **نعم** (lite صغير، وstandalone مضغوط) | PyInstaller: كبير عادةً | **صغير جداً بلا runtime** |
| إنذارات مضاد الفيروسات الكاذبة | قليلة | **شائعة مع PyInstaller**، وهذا يضر بأداة تثبيت برامج | قليلة |
| السجل وتشغيل المثبّتات وUAC وقراءة PE/MSI | أصلي وسهل | ممكن لكن بحزم إضافية | ممكن بجهد أكبر |
| سرعة فحص آلاف الملفات وحساب البصمات | **عالية** | أبطأ في المنطق (البصمة نفسها سريعة بمكتبة أصلية) | عالية |
| ما أُنجز | **نحو 240 اختباراً وكل المنطق** | يُعاد كله | يُعاد كله |
| كلفة الصيانة | كود واحد | **كودان يتباعدان** وتُضاعَف الاختبارات | كودان |

**لماذا لا نسخة ثانية:** كل ما يميّز المشروع (المطابقة وقراءة الملفات وتصديرها واستيرادها ومكتبة الملفات) موجود مرة واحدة في `WingetOffline.Core` ومختبَر. نسخة بلغة أخرى تعني إعادة كتابة كل ذلك وإبقاءه متطابقاً إلى الأبد، وأي اختلاف في المطابقة أو ترتيب الإصدارات يصير خطأً يصعب كشفه.

**متى نعيد النظر:**
* إن احتجنا لاحقاً أداة **صغيرة جداً بلا runtime** (مثل Agent الإصدار 0.3)، نجرّب أولاً **Native AOT لتطبيقات الـ console في C#** ونقيس الحجم، قبل التفكير بلغة أخرى.
* Python يبقى مناسباً **كلاصق** للسكربتات: يقرأ مخرجات `wgo --json` أو ملفات التصدير. لا يحتاج نسخة موازية من المشروع.

## هل نوقف تطوير `wgo`؟

**القرار: لا نوقفه، لكن يبقى رقيقاً.**

* هو واجهة سطر الأوامر لمحرك `Core` نفسه، فكلفة إبقائه قليلة (كل المنطق في Core).
* يخدم الأتمتة (سكربتات وجدولة) والأجهزة بلا واجهة والتشغيل الآلي في الاختبارات، وهو ما نتحقق به من المنطق خارج WPF.
* هو الأساس الطبيعي لـ Agent الإصدار 0.3، وطريق الإنقاذ إن تعطّلت الواجهة.
* **القاعدة:** لا منطق داخل `wgo`. ميزة جديدة تُكتب في Core مع اختبارها أولاً، ثم يُضاف لها أمر في `wgo` إن كان له نفع. ولا ميزة تُبنى في `wgo` وحده.

## لماذا `wgo` و`Builder` برنامجان منفصلان؟

الأدوات غير المتصلة (التطبيق و`wgo`) لا تحوي أي كود تنزيل، فيمكن التحقق من أنها لا تلمس الشبكة. دمجها مع `Builder` كان سيضيّع هذا الضمان. تفاصيل خطة الشبكة المحلية للإصدار 0.3 في [FLEET.md](FLEET.md).

## لماذا لا نترجم `WingetOffline.exe` إلى ملف صغير بلا .NET؟

تطبيق WPF لا يدعم Native AOT ولا التقليم (trimming)، فإما ملف صغير يحتاج .NET مثبّتاً (lite)، أو ملف كبير يحمل .NET (standalone). هذا قيد من منصة WPF لا من المشروع.
